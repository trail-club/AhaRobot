# LeKiwiベースのキャリブレーションと精度評価

対象はアームを外したLeKiwi機体1の3輪オムニベース。アーム・頭部サーボの校正とは別に扱う。
2026-10-25の実機条件、測定値、採用理由、生データは
[モーターの検証記録](context/motor.md#2026-10-25--lekiwi機体1のオドメトリと横移動の校正)を参照。

## 評価する量

`base_driver.py` は `/cmd_vel` (`geometry_msgs/msg/Twist`) を購読し、サーボへ速度指令を送る。
`/cmd_vel` を配信する側は試験ノードなどであり、ドライバ自身ではない。
以下の2種類を区別して測定する。

| 評価 | 入力・終了条件 | 比較する値 |
| --- | --- | --- |
| オドメトリ・運動学 | エンコーダの目標距離・角度まで移動して停止 | エンコーダ変位と独立したLiDAR照合変位 |
| 速度指令追従 | 同じ `/cmd_vel` を一定時間、一定周期で配信して停止 | 指令積分量とエンコーダ・LiDARの変位、所要時間 |

目標距離で停止する試験の結果を、一定速度・一定時間の試験結果として記載しない。
位置・向きは区間開始時の `base_footprint` 座標へ変換する。
走行中の測定は `/odom`、必要に応じて `odom → base_footprint` TFを使う。
独立した基準は静止した前後の生 `/scan` のICP照合とする。
LiDAR推定には照合誤差があるため「真値」やメジャー実測と同一視しない。

## 調整するパラメータ

| パラメータ | 単位・役割 |
| --- | --- |
| `wheel_radius` | m。エンコーダ回転と並進距離の倍率 |
| `base_radius` | m。車輪中心の配置半径とその場回転の倍率 |
| `wheel_angle_offset_deg` | deg。車体座標に対する車輪運動学の共通方向オフセット |

方向符号、モーターID、レーザーの取付TFを先に確認する。
車輪角の変更は並進方向とエンコーダ座標へ影響する。単一方向のみで決定せず、前後左右で方向差を比較する。
共通半径だけで、車輪ごとの差、左右差、床面の滑りを補正できるとは限らない。

並進倍率 `s_l = LiDAR移動距離 / エンコーダ移動距離`、
回転倍率 `s_a = LiDAR回転角 / エンコーダ回転角` を有効区間から推定する。
`r_new = r_old × s_l`、`R_new = R_old × s_l / s_a` とする。
方向は `wrap(atan2(y_lidar,x_lidar) - atan2(y_odom,x_odom))` の中央値を候補とし、
この実装では現在の `wheel_angle_offset_deg` に加える。別区間で符号・改善を検証して採用する。

## 測定環境と動作セット

平坦な床で機体・床面・荷重・壁の位置・ケーブル配置を記録する。
前後左右の各直線を往復し、回転は左右360°を組にする。
90°の静止スキャン照合では死角が変わり、比較可能な点が不足する場合がある。
短い区間で測定できても、3 m走行や別の床面の精度を保証しない。

走行前に機体の周囲と回転時の車輪・ケーブルの可動域を確認する。
観測できない方向へ距離を増やさない。物理停止操作ができる状態で試験する。
終了・例外時はゼロ速度を送り、ドライバを正常終了してトルクOFFを読み戻す。

一定時間の試験は、初めに低速・短時間で前後・左右を対にする。
指令の速度、周期、実送信時刻、送信時間、停止後の変位を保存する。
加減速・停止後の惰性を含む区間平均速度と、定常速度は分けて評価する。
回転も `wz × 時間` と連続アンラップ角を比較し、角度の±π境界を扱う。
オドメトリ欠測、距離余裕不足、時間超過時には停止し、中断を正常試験へ数えない。

## 近距離の囲いでのLiDAR照合

2026-10-25の測定用構成はSensitivityモード、20スキャン、静止待ち2秒。
角度ごとに中央値を取り、70%以上で観測されMADが12 mm以内の点を採用する。
センサー距離0.10–8 m、車体座標の半径0.22 m以内を除外し、5 mmでダウンサンプルする。

ICPの対応距離は80→40 mm、初期角は±30°まで複数試行する。
一致率60%以上、RMS20 mm以内、最小固有値0.005以上に加え、
逆方向の照合でも一致率60%以上・RMS20 mm以内、逆変換とのずれ15 mm未満・1.5°未満を要求する。
照合失敗区間は補正値の計算へ入れない。
これらは当日の補助ツールの条件で、既存 `calibrate_odom` 本体の既定値ではない。

## 記録と反映

結果は日時、機体、コードリビジョン、設定、動作・終了条件、各区間の変位、
照合品質、失敗理由、反映先、独立した再試験の結果と一緒に `docs/context/motor.md` へ追記する。
数値データは `docs/context/data/`、大きな動画は保存先への参照を残す。
実機走行動画とLiDAR・オドメトリの再生表示を区別する。

機体1で採用した設定ファイルは [YAML](context/data/lekiwi-20261025/base_robot1_calibrated_20261025.yaml)。
DGXでは `/home/shun.kodaira/maps/base_robot1_calibrated_20261025.yaml` に保存し、
LeKiwiリポジトリの `docker/robot/.env` の `BASE_PARAMS_FILE_1` で選択する。
その作業ツリーでは `make run-base ROBOT=1` と `make run-base-map ROBOT=1` がファイルを渡す。
AhaRobotの通常起動や別機体へ自動反映された設定ではない。

設定調整で改善した場合、`base_driver.py` の変更自体は必須ではない。
変更する場合は上流リポジトリで行い、このリポジトリのsubmodule運用に従う。
